## 1. 目的

走行中に「現在地点（km）と現在時刻」を手入力する P-5 は、走りながら距離を読み取って打ち込む手間がある。ワンタップで端末の GPS と現在時刻を取得し、コース上の位置に変換して P-5 の再計算を自動で行えるようにする。

## 2. 利用場面と前提

- PC や休憩中、信号待ちなどの**停車中に片手でタップ**する。走行中の操作は想定しない。
- iPhone Safari（通常表示・ホーム画面追加の両方）で動作すること。位置情報の取得は HTTPS が必須で、GitHub Pages はこれを満たす。
- コースはすでに読み込まれ、出走日時・グロス速度・仮眠が設定済みであること。未設定ならボタンを無効化し、理由を表示する。
- 圏外でも位置取得（GPS 自体は通信不要）と通過時刻の再計算は動き、予報の再取得だけが失敗し得る。この場合はキャッシュ済みの予報で表示を更新する。

## 3. ユーザーから見た動作

1. 画面上部の要点表示の近くにボタン **「現在位置から予報を再取得」** を置く。
2. タップすると iOS の位置情報許可ダイアログが出る（初回のみ）。
3. 取得中は「位置を取得中…」→「予報を更新中…」の 2 段階で進行を表示する。3〜10 秒程度を想定。
4. 成功すると次が更新される。
   - 要点表示：ゴール予定時刻、残りの向かい風区間 km、残りの雨中走行 km、以降の最低気温
   - リボン：現在地に縦のマーカーを立て、通過済み区間を薄く表示。以降の通過時刻を再計算した位置に時刻目盛を引き直す
   - 区間表：現在地より先の行の通過時刻・予報を更新。通過済みの行は残すが薄く表示
   - ステータス行：「現在地 236 km ・ 10:42 取得 ・ GPS 精度 ±35 m ・ 予報 09:00 発表」
5. 失敗時はエラーの理由と、代替手段（P-5 の手入力欄へのリンク）を表示する。

## 4. 機能要件

### 4.1 位置情報の取得

| ID | 要件 |
|---|---|
| R-1 | `navigator.geolocation.getCurrentPosition` を 1 回だけ呼ぶ。`watchPosition` は使わない（電池と許可の観点） |
| R-2 | オプション：`enableHighAccuracy: true`、`timeout: 15000`、`maximumAge: 0` |
| R-3 | 取得結果の `coords.accuracy`（m）を保持し、画面に「GPS 精度 ±nn m」として表示する |
| R-4 | 許可拒否（`PERMISSION_DENIED`）のときは「位置情報の利用が許可されていません。iPhone の 設定 → プライバシーとセキュリティ → 位置情報サービス → Safari で許可してください」と案内し、手入力へのリンクを出す |
| R-5 | タイムアウト・取得不能のときは「位置を取得できませんでした。空が開けた場所で再度お試しください」と案内し、手入力へのリンクを出す |
| R-6 | 位置情報は端末内でコース上の距離に変換するためだけに使い、外部に送信しない。予報の取得に使う座標はコースのサンプル点であり、現在地そのものではない（プライバシー方針として画面の説明に明記） |

### 4.2 コース上の位置への変換

| ID | 要件 |
|---|---|
| R-7 | 現在地からコースの各セグメント（間引き前のトラック点列、または 100 m 以下の間隔に再サンプリングした点列）への最短距離を求め、最も近い点の「スタートからの距離 km」を得る |
| R-8 | **走行中判定**：最短距離が 1,000 m 以内なら走行中とみなす。これを超える場合は「コースから約 n km 離れています。コース上に戻ってから再取得するか、距離を手入力してください」と表示し、再計算は行わない |
| R-9 | GPS 精度が悪い場合（`accuracy` > 500 m）は、最短距離が 1 km 以内でも「精度が低いため位置がずれている可能性があります」と警告を添え、再計算は実行する |
| R-10 | **重複区間の扱い**：往復や周回でコースが同じ道を 2 回以上通る場合、1 km 以内に複数の候補（距離が 5 km 以上離れた極小点）が存在し得る。候補が複数あるときは次の順で決める：(a) 前回の再取得や手入力で得た距離より先で、かつそこから経過時間×グロス速度×1.5 以内の候補を優先、(b) 前回の位置がなければ計画上の現在時刻に対応する距離に最も近い候補を優先、(c) それでも候補間の差が 20 km 以上あるなら「どちらですか？」と候補を距離付きで並べ、利用者に選ばせる |
| R-11 | 確定した距離を `currentKm`、取得時刻を `currentTime` として P-5 と同じ状態に書き込む。以降の処理は P-5 と共通 |

### 4.3 現在時刻の取得

| ID | 要件 |
|---|---|
| R-12 | まず NICT の JSON 時刻サービス（`https://ntp-a1.nict.go.jp/cgi-bin/json` または `ntp-b1`）を `fetch` し、サーバ時刻 `st`（UNIX 秒）を得る。送信直前と受信直後の端末時刻から往復時間を測り、その半分を加えて補正する |
| R-13 | NICT へのアクセスが失敗（圏外、CORS 拒否、タイムアウト 3 秒）した場合は端末時計 `Date.now()` を使い、ステータス行に「端末時計」と小さく表示する。iPhone の時計はキャリア／NTP 同期されているので実用上の差は小さい |
| R-14 | NICT 時刻と端末時計の差が 60 秒を超える場合は NICT を採用しつつ「端末の時計が n 秒ずれています」と表示する |
| R-15 | 位置取得と時刻取得は並行して行い、位置の `timestamp` と時刻取得の差が 30 秒を超えたら位置取得をやり直すか、その差を表示する |

### 4.4 再計算と予報の再取得

| ID | 要件 |
|---|---|
| R-16 | 通過時刻の再計算は P-5 の関数をそのまま使う。`currentKm` より先の区間に、設定済みのグロス速度と仮眠を適用する |
| R-17 | 仮眠ポイントのうち距離が `currentKm` 未満のものは「消化済み」として以降の計算から外す。`currentKm` の ±2 km 以内にある仮眠ポイントは「これから仮眠しますか？」と 1 タップで確認し、既定は「する」 |
| R-18 | 予報の再取得は `currentKm` 以降のサンプル点のみを対象に Open-Meteo（MSM）へ 1 リクエスト投げる。通過済み点の予報は再取得せず、表示は前回値を薄く残す |
| R-19 | 予報の取得に失敗（圏外）した場合は、キャッシュ済みの前回予報に新しい通過時刻を当てはめて表示し、ステータス行に「予報は hh:mm 取得のもの（更新できませんでした）」と表示する |
| R-20 | 再計算後の要点表示は「残り」ベースに切り替える：ゴール予定、残りの向かい風 km、残りの雨中走行 km、以降の最低気温 |
| R-21 | 再取得のたびに「距離・時刻・精度」の履歴を端末内に保持し（最大 50 件）、R-10 の候補判定と、区間表の「実績」列（任意）に使う |

### 4.5 UI

| ID | 要件 |
|---|---|
| R-22 | ボタンは 44 pt 以上の高さで、要点表示の直下に全幅で置く。ラベル「現在位置から予報を再取得」、取得中はラベルを進行状況に置き換え二重タップを防ぐ |
| R-23 | 成功後 3 秒間、ボタンの下に「236 km 地点として再計算しました」と結果を短く表示する |
| R-24 | 手入力（P-5）の欄は残し、ボタンの近くに「距離を手で入力する」リンクを置く。GPS 取得後に手入力で上書きもできる |
| R-25 | 設定に「デバッグ：位置を手入力してテスト」を隠し項目として置き、緯度経度と時刻を直接入れて同じ処理を通せるようにする（実機がコース上にないと試験できないため） |

## 5. エラーと表示文言（一覧）

| 状況 | 表示 |
|---|---|
| 位置情報の許可なし | 位置情報の利用が許可されていません。設定 → プライバシーとセキュリティ → 位置情報サービス → Safari で許可してください |
| 取得タイムアウト | 位置を取得できませんでした。空が開けた場所で再度お試しください |
| コースから 1 km 超 | コースから約 n km 離れています。コース上で再取得するか、距離を手入力してください |
| 候補が複数 | 現在地に近いコース上の地点が複数あります。どちらですか？［123 km 付近］［412 km 付近］ |
| 精度が悪い | GPS 精度が ±nn m と低いため、位置がずれている可能性があります |
| 予報を更新できない | 予報は hh:mm 取得のものです（更新できませんでした） |
| NICT 不達 | （ステータス行に）端末時計 |
| コース未読み込み | 先にコースを読み込み、出走日時と速度を設定してください |

## 6. 非機能要件

- 位置取得から画面更新まで、通常 10 秒以内。
- 位置情報はメモリ上と端末内履歴（R-21）にのみ保持し、サーバへ送らない。履歴はコースを読み替えると消去する。
- 位置取得の失敗が続いても、既存の手入力（P-5）と表示は影響を受けない。

## 7. 実装メモ

- 最短距離の計算は、コース点列を 100 m 間隔に再サンプリングしたうえで「点から線分への垂線距離」を全セグメントで求める。600 km で約 6,000 セグメント、iPhone でも数十 ms で終わる。座標は平面近似（緯度 1° ≒ 111 km、経度 1° ≒ 111 km × cos(緯度)）で十分。
- 極小点の抽出：セグメントごとの距離配列を走査し、前後より小さく 1 km 以内のものを候補にする。5 km 以内で連続する候補は 1 つにまとめる。
- NICT の JSON レスポンス例：`{"id":"ntp-a1.nict.go.jp","it":0.000,"st":1757200000.123,"leap":36,"next":1483228800,"step":1}`。`st` がサーバ時刻。**CORS ヘッダの有無は実装時に実機で確認すること。** 取れなければ R-13 のフォールバックが常に使われるだけで、機能は成立する。
- 時刻取得は `Promise.race` で 3 秒のタイムアウトを付ける。
- 通過済み区間の「薄く表示」は、リボン・区間表とも既存の描画に `past` クラスを付けて opacity を下げるだけにし、描画ロジックは分けない。
- テストは R-25 のデバッグ入力で行う。テストケース：(1) コース上 1 点、(2) コースから 3 km 離れた点、(3) 往復コースの重複区間、(4) 仮眠ポイント直前・直後、(5) 圏外を想定して fetch を失敗させる。

## 8. 受け入れ条件

1. iPhone 実機でボタンをタップすると許可ダイアログが出て、許可後にコース上の距離と時刻が表示される
2. コースから 1 km 超の地点ではエラーになり、再計算は行われない
3. 往復コースの重複区間で候補が 2 つ出る場合、選択 UI が表示され、選んだ方で再計算される
4. 再計算後、ゴール予定時刻・残りの向かい風 km・残りの雨中走行 km が更新され、リボンに現在地マーカーが立つ
5. 機内モードでタップしても、通過時刻は更新され、予報は前回値のまま「更新できませんでした」が表示される
6. 手入力（P-5）が従来どおり使える
